# Лендинг для обжарки «Кварта»

Тестовое задание: создание лендинга с формой заявки, валидацией и защитой от дублей.

## Архитектура и стек
- **Frontend:** React + TypeScript + Vite (сгенерировано через Lovable.dev, доработано вручную), Tailwind CSS, React Hook Form, Zod.
- **Backend:** Node.js + Express + TypeScript, Prisma (SQLite), Zod для валидации.
- **Сеть:** Cloudflare Tunnel (для проброса локального бэкенда на домен `api.zilserver.uk`), Cloudflare Pages (деплой фронтенда).

## Распределение работы: ИИ vs Ручная работа

### Что сгенерировал ИИ (Lovable.dev)
- Первичная верстка UI-компонентов (Hero, карточки товаров, форма) и базовая структура Tailwind-классов.
- Шаблоны конфигурационных файлов Vite.

### Что сделано самостоятельно
- Архитектура Monorepo (разделение `client` и `server`).
- Настройка бэкенда: Express, Prisma Schema, миграции SQLite.
- **Бизнес-логика формы:** интеграция React Hook Form с Zod, логика таймера обратного отсчета (10 минут) на фронтенде и дублирующая проверка на бэкенде.
- Настройка Cloudflare Tunnel и переменных окружения (`VITE_API_URL`).
- Очистка проекта от ненужного boilerplate (Supabase, Drizzle), добавленного ИИ по умолчанию.

### Где ИИ ошибся и как это было замечено
1. **Валидация телефона:** ИИ не учел, что маска ввода на фронтенде добавляет пробелы и дефисы (например, `+375 29 123-45-67`), а строгий regex на бэкенде их отвергал (ошибка 400 Bad Request). 
   *Решение:* Я добавил в Zod-схему метод `.transform()`, который очищает строку от пробелов и скобок *перед* проверкой по регулярному выражению.
2. **Маршрутизация API:** ИИ прописал относительный путь `/api/lead`. При деплое на Cloudflare Pages это приводило к ошибкам.
   *Решение:* Внедрены переменные окружения `.env` и `.env.production` с явным указанием `VITE_API_URL`.
3. **Лишние зависимости:** Lovable по умолчанию добавил конфигурации Supabase и Drizzle. Это было замечено при анализе `package.json` и `.env`, после чего все лишние пакеты и папки были удалены для чистоты сборки.

## Что не успели / сделали бы иначе при наличии времени

- Развернуть бэкенд не на локальном ПК через туннель, а на полноценном хостинге (например, Render или Railway) для обеспечения 100% аптайма без зависимости от моего компьютера.
- Добавить unit-тесты для Zod-схем и контроллера.
